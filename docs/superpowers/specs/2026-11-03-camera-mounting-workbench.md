# 个人版相机挂载工作台重构

## 目标与范围

将个人版相机挂载从地图上的叠加详情卡，整理为连续的地图工作台流程。沿用 SeeTime 平台外壳、现有项目/城市/相机/POI 示例数据、地图 SDK、本机存储、反馈和车位标定能力；不把参考图中的南京示例数据写入当前项目。

## 交互结构

- 地图是主视图，POI/AOI 目录可折叠；地图图例默认收起。
- 工作区首页保留 POI 维度查看挂载关系，并可切换到项目待处理相机队列。
- 相机入口按“核对相机 → 选择 POI → 确认挂载”分步展示；选 POI 阶段提供 AI 候选、附近 POI、项目全部 POI 横向切换。
- POI 入口沿用“选择相机 → 核对相机 → 确认当前 POI”语义，当前 POI 是固定目标，不出现目标选择器。
- 相机核对展示画面、元素、检测要素、安装位置与水印；保留编辑、反馈、百度全景/车位标定等现有能力。
- 确认阶段只展示本次相机与目标 POI 摘要。保存前地图只显示预览连线；显式保存后才变为正式已挂载状态。
- 完成态展示保存结果，支持处理下一台或回到原 POI 工作区。
- 新增 POI 与相机挂载关系分开保存。标记无法挂载保留为独立动作。

## 响应式与数据边界

- 延续现有深色主题和平台导航；桌面维持目录、地图、工作区三栏，窄屏将工作区以抽屉呈现。
- 地图 marker 点击必须保留当前入口/固定 POI 语义。
- AI 候选、附近线索、未保存预览、正式挂载四种状态不能混淆。
- 车位轮廓只回显已保存的真实示意标注，不虚构检测几何。

## 验收标准

1. 项目队列、POI 工作区、相机核对、POI 选择、确认、完成六种视图均可达。
2. 相机入口可以完成选 POI、预览、显式保存；保存后地图关系、POI 状态、相机挂载状态一致。
3. POI 入口从候选/附近进入后目标固定；地图相机 marker 不丢失该目标，保存后返回同一 POI。
4. 新建 POI 不自动挂载相机；取消不产生目录/关系变更。
5. 车位标定原有绘制、数量约束、保存和详情回显不回退。
6. 1440×900、1920×1080 与窄屏视口中关键操作可见且不互相遮挡。

## 决策记录 D-001

**候选方案**：A. 同一页面状态式工作台；B. 独立路由向导；C. 地图卡片上追加模态步骤。

**评审组成**：产品经理、UX 设计师、前端架构/QA。

**结论**：采用 A。产品与 UX 评审均推荐单工作台复用地图与 POI 上下文；技术评审确认现有单页状态和地图 SDK 足够支撑，拆路由会增加上下文/回流风险。

**反方审查**：最大风险是模式状态复杂和窄屏地图空间被工作区挤压。用明确 `workflowStep` 和入口模式、桌面/窄屏不同布局处理；不另造挂载存储或地图 SDK。

**投票**：A 3 票，B 0 票，C 0 票。

**风险**：中。
